# نموذج إلزامي لتتبع مسار عمل عند المراجعة

> انسخ هذه الاستمارة لتقرير مراجعة حقيقي، ولا تعامل الأمثلة كدليل نجاح. اكتب «غير مفحوص» عندما ينطبق.

## معلومات الدليل

- الموديول / المجال المالك:
- الفرع + SHA الحالي:
- SHA آخر تحقق سابق (إن وجد):
- تاريخ المراجعة واسم السيناريو:
- وضع التشغيل / القطاع / الباقة / البلد / العملة:
- ملفات تغيرت من آخر مراجعة، وتأثير الكور المشترك:
- مستوى التغطية: مراجعة كود / اختبار فعلي / قبول مستخدم / امتثال رسمي

## خط التنفيذ الكامل

| الطبقة | المسار / الدالة / العنوان | حالة المراجعة وأثر الخطأ |
| --- | --- | --- |
| الشاشة أو مدخل العميل | route وملف component، بما فيه Electron / Android / POS | غير مفحوص |
| اتصال الواجهة | API method وpayload وcache invalidation | غير مفحوص |
| Controller / DTO | URI والـDTO والـvalidation | غير مفحوص |
| الحُراس | tenant + role + permission + feature + app mode | غير مفحوص |
| خدمة الأعمال | service/function والتفويض للحساب والمخزون | غير مفحوص |
| الذرّية والتزامن | transaction وlock order وidempotency والتراجع عند الفشل | غير مفحوص |
| مخطط البيانات | migrations وFK وtenant_id وunique والبيانات القديمة | غير مفحوص |
| دفتر المخزون | الموقع والكمية والحجز والتكلفة والحركات | غير مفحوص |
| القيد والدفاتر المساعدة | post/reverse/GL/AR/AP/treasury مع period/currency | غير مفحوص |
| التقارير والإقفال | اتزان ونتائج التسويات مع المستند المصدر | غير مفحوص |
| الاختبارات | اختبار الوحدة والتكامل والواجهة/النشر/UAT بنتيجة صريحة | غير مفحوص |

## اختبارات واجبة بحسب الأثر

- المسار الطبيعي، الخطأ في منتصف المعاملة، وتكرار الطلب (replay/idempotency).
- طلبان متزامنان على نفس الرصيد أو المستند؛ قفل المخزون/الفترة/الشريك.
- المستأجر الآخر، مستخدم غير مصرح له، خطة غير مستحقة، تشغيل Cloud أمام Desktop.
- الإلغاء أو العكس، المرتجع، التسوية، الحسابات المدينة والدائنة، كمية وتكلفة المخزون.
- عملة مختلفة وتقريبها، ضرائب وقوانين البلد، تواريخ الفترات.
- نسخة فعلية محلية وأوفلاين وترقية/استعادة عند تعلق الموديول بها.

## نتيجة قابلة للتحقق

- ما ثبت (بالدليل + اسم الاختبار + نتيجته + تاريخ التشغيل + SHA):
- ما كُتب له اختبار لكن لم يُشغّل:
- ما لم يُقرأ/لم يُختبر:
- العيوب P0 / P1 / P2 وروابط الإصلاح:
- التأثير على الموديولات المشتركة:
- موانع الإصدار الحالية:
- التوصية: `unverified_current_head` / `verified_scoped` / `release_blocked` / `release_ready`
- رابط PR/Commit ودليل التشغيل وقرار القبول:

**لا تُستخدم `release_ready` دون تحديد الأسواق وأوضاع التشغيل المشمولة وإثبات القبول المطلوب لها.**
